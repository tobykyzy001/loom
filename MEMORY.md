# Implementation memory

## Scope and workflow

- User requested implementation of the full roadmap with coordinator-managed subagents, incremental commits and a problem/solution memory. First version skips the 1 Concierge + 3 Node Compose topology; deterministic single-node and direct protocol benchmarks have priority.
- Initial checkout on 2026-11-17 contains only design documents. `main` was clean and five documentation commits ahead of `origin/main`. Do not claim existing commits were pushed or external platforms were verified.
- Rust 1.99, Cargo 1.99, Node 24.21 and pnpm 12.10 are present. DSH Desktop's `desktop` profile is present, but no live Cordis inspect tools are exposed. Any host implementation must use the installed DSH sources and clearly distinguish logical/plugin tests from installed-host validation.

## Decisions

- 2026-11-17: implement protocol/domain in Rust and independently validated language-neutral JSON contract fixtures; TypeScript shares JSON fixtures rather than Rust ABI.
- 2026-11-17: bootstrap with Axum/Tokio and bundled rusqlite, Vue 3 + TypeScript, and a workspace-local installable plain ESM DSH bundle. Transport is explicit long-poll HTTP for the baseline, not falsely described as an outbound WebSocket.
- Keep user instruction, Task state, Grant, Assignment/Lease, Effect, structured Report, Artifact and view preferences separate. Client authentication is mandatory; no unauthenticated development bypass in production defaults.
- Default test fixtures use synthetic data and no Live LLM calls. Do not mutate the running DSH profile or real user projects during tests.

## Task ownership and integration checkpoints

- `agent-1` owns protocol/domain, Rust workspace root and JSON protocol fixtures. Do not commit; coordinator integrates.
- `agent-2` owns Vue app/root TS package files. `agent-3` owns TypeScript node client, installable DSH plugin and deterministic baseline. Neither may touch user runtime profiles.
- Coordinator owns Rust Concierge and bare node, integration, MEMORY/development documentation, final diff and commits.

## Bounded transport credentials, cancellation and durable retry

- **Close a real credential fall-back:** `LoomHttpClient` previously compared the provided token with the client token but then selected `(token || clientToken)` for the Authorization header. Consequently a missing node credential—or a whitespace token accepted into identity state—could pick up a client/admin token on a `/nodes/` transport. Node routes excluding *only* explicit `challenge` and `register` anonymous calls now require a supplied nonblank node token **before fetch**; explicit noAuth on heartbeat/report/poll/artifact is rejected, and re-enrollment may use the actual old Node token. There is no fallback private principal substitution. Admin/client HTTP uses its own independent route and does not change access by being present in the same instance. Registration output with whitespace is rejected before identity goes onward; it cannot become a usable/bearer substitute or leaker of the wrong private token. The controller remains the last authorization gate, not the reason to permit an outbound leak.
- **Reject cancellation before beginning new transport and re-check after fetch/body points.** `signal.aborted` now prevents any `fetch()` at all on already-cancelled calls. A late response that says an empty assignment cannot become an idle result after a local abort; caller cancellation is not server-level acknowledgement. `poll` and assignment construction respect that failing status instead of manufacturing or reading a false current Assignment. Existing ordinary time limits, byte cap and node-scoped authorization are preserved; this is a node-transport boundary, not a claim about cancelling effects already sent/executed remotely.
- **Outbox caller cancellation is not a normal retry error.** `dispatchOutbox` used to convert the caller's shutdown signal into `deferred`, increment attempts and advance the backoff. It already kept the queue (not actual loss) but behavior/telemetry was misleading. In the catch path, the dispatch's own aborted signal now propagates its original reason **before mutating attempts/backoff or processing the next item**. Pending bodies and logical IDs remain. Ordinary network failure and configured timeout still retain the exact unknown-report body and can retry after due; 401/403/409/410/422 quarantine remains distinct. No external effect is said to be cancelled, acknowledged or exactly-once solely because the caller stopped.
- **Evidence is public behavior, not snapshots alone.** `packages/node-client/test/transport-boundary.test.js` creates owned identities/states and verifies zero outbound calls on missing/whitespace/admin tokens, anonymous whitelist, legitimate old-node-token re-enrollment, cancellation stop without processing the next entry, normal retry with original request ID and configured-timeout ordinary backoff. The older two HTTP tests were strengthened for pre-cancel/no-fetch and timeout not producing an Assignment. `plugins/dsh-loom/test/http-transport.test.js` separately imports the vendored public bundle to verify that equivalent `node credential` and two pending events survive shutdown and delivery can later be retried. **Node client 20 / plugin 54 pass.** Both primary HTTP and identity helpers are byte-identical; plugin PATCH helper is aligned too without widening Node permissions. Its existing worker ID default was deliberately left alone.
- **Final review caught identity-state rollback, not just an outbound guard:** even with whitespace rejected, `setToken` originally assigned into live memory before validation, losing the previous working credential for the current run. Move candidate validation before mutation and perform the safe identity-file replacement before `Object.assign` to live data. Invalid response or failed atomic write preserves valid runtime credentials. The driver explicitly reuses the working credential in a following heartbeat, and a non-null assignment canceled *during body consumption* can no longer be admitted to `poll`. This is separately asserted, rather than assuming the new preflight abort test covers the durability race.
- **Source facts:** actual isolated DSH install/registration/Tool/file-effect/cancel/resume and credential unknown→delete→unseeded missing pass after this change alongside the original Rust workspace and clippy, Git and bare integration. There is no real remote second host or current Profile mutation, no external credential reading, live paid model, real-user secret entry, network discovery or undeclared background retry job. These mocks/owned probes validate the transport boundary; older Mock Headless process behavior is not interchangeable with further external deployment evidence. Detailed command/limit: [tests/harness/EVIDENCE.md](tests/harness/EVIDENCE.md). ## Bounded HTTP response streaming

- Native Web Stream responses no longer force `arrayBuffer()` before enforcing maxResponseBytes. Shared and vendored `src/http.js` accumulate actual `Uint8Array` chunks, terminate at the first overflow with one reader.cancel, then concatenate only accepted bytes before the existing TextDecoder/JSON/status logic. A false small `Content-Length` cannot bypass the cap; an oversized declaration with an actually valid small body still parses. Exact boundary, split UTF-8, empty body and old no-stream fixture compatibility are separately tested. The fallback still has its pre-allocation limitation and isn't advertised as universally stream-limited.
- **Reader wakeups and error priority are explicit**: read is raced with the existing internal AbortController, which combines total timeout and the caller's signal. Caller cancellation has final precedence even when reader/fetch/cancel rejects another reason; internal timeouts settle too. Cleanup invokes `reader.cancel()` without making another indefinite wait around a non-settling cancel Promise and keeps the primary error. Never interpret a local HTTP reader failure as an authorization/Effect result. Successful stream completion can't be claimed as remote effect cancellation or exactly-once. Chunk based timing counts as data is not a permission or server proof.
- Zero-length chunks don't grow logical JSON bytes, but must yield the event loop (`setTimeout(0)`), while also checking the cancellation watcher. Million-frame resolved-promise starvation is addressed. `getReader` availability is now by actual function, and fallback is checked for caller cancellation before reading. Invalid cap/config gets bounded TypeError. Empty/no-data response still returns null and HTTP error status and error code remain distinguishable from transport errors.
